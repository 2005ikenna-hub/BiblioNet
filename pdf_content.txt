1. Contexte
La bibliothèque d'un établissement scolaire gère aujourd'hui ses ouvrages et ses prêts sur
des cahiers. Il est difficile de savoir si un livre est disponible et qui l'a emprunté. La direction
souhaite une application web simple, accessible en ligne, pour gérer les livres, les
adhérents et les emprunts.
Votre équipe de 3 développeurs dispose de 4 jours pour concevoir cette application en
respectant l'architecture MVC (Modèle – Vue – Contrôleur), puis la mettre en ligne à
une adresse accessible depuis Internet.
2. Objectifs pédagogiques
À l'issue du mini-projet, l'étudiant doit être capable de :
• comprendre et appliquer le patron d'architecture MVC sans framework ;
• mettre en place un point d'entrée unique (front controller) et un routeur simple ;
• accéder à une base MySQL de façon sécurisée avec PDO et des requêtes préparées ;
• gérer une authentification par session ;
• travailler à plusieurs sur un même code avec Git et GitHub ;
• déployer une application PHP/MySQL sur un hébergement et la rendre accessible par une
URL publique.

3.3 Contraintes techniques
• Langage : PHP 8.x orienté objet, sans framework (pas de Laravel ni Symfony) ;
• Base de données : MySQL / MariaDB, accès via PDO et requêtes préparées uniquement ;
• Interface : HTML5 et CSS3, Bootstrap fortement conseillé pour gagner du temps ;
• Aucune requête SQL dans les vues ; aucun HTML dans les modèles ;
• Toutes les données affichées sont échappées avec htmlspecialchars (anti-XSS) ;
• Code versionné sur un dépôt GitHub commun ; chaque membre commite son propre
travail.

4.3 Exemple de flux d'une requête
L'utilisateur ouvre /livres → le fichier .htaccess redirige vers public/index.php → le Router
appelle LivreController::index() → le contrôleur demande les données à Livre::all() → il
transmet le résultat à la vue views/livres/index.php → la page HTML est renvoyée au
navigateur.
# public/.htaccess
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ index.php?url=$1 [QSA,L]
5. Modèle de données (4 tables)

id, nom, prenom, classe, telephone
emprunts
id, livre_id (FK), adherent_id (FK), date_emprunt, date_retour (NULL tant que le

Règle métier : exemplaires disponibles = nb_exemplaires − nombre d'emprunts du livre dont
date_retour est NULL. Si le résultat vaut 0, le livre est indisponible et l'emprunt est refusé.

8. Mise en ligne de l'application
L'application doit être accessible depuis Internet à une URL publique. Pour tenir les délais,
l'hébergement mutualisé est recommandé (cPanel ou équivalent : hébergeur local ou offre
gratuite comme InfinityFree ou AlwaysData). Un déploiement sur VPS est accepté pour les
groupes avancés.
8.1 Procédure type
1. Créer la base de données et l'utilisateur MySQL depuis le panneau d'hébergement.
2. Importer le fichier database/biblionet.sql via phpMyAdmin.
3. Transférer le projet (FTP avec FileZilla, ou git clone si SSH disponible).
4. Faire pointer la racine du site vers le dossier public/. Si ce n'est pas possible, placer un
.htaccess à la racine redirigeant vers public/.
5. Créer le fichier .env sur le serveur avec les identifiants de production (jamais envoyé sur
GitHub).
6. Désactiver l'affichage des erreurs en production (display_errors = Off).
7. Tester toutes les fonctionnalités en ligne et créer un compte de démonstration pour le
jury.
